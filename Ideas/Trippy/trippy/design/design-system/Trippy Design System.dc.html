01 — Brand Personality

What Trippy feels like

Every visual decision — a button radius, a shadow depth, a transition curve — should resolve the core tension: solo travellers need to feel excited and safe at the same time. These five adjectives are the filter.

🌊
Warmly adventurous

Adventure without arrogance. Trippy should feel like your most well-travelled friend — genuinely excited about where you're going, not intimidating about having been there first. Energy without edge.

🤝
Community-first

The product exists to fight loneliness on the road. Design decisions that surface people — faces, names, compatibility — get the best real estate. Trip cards show the humans going, not just the destination.

🛡️
Quietly trustworthy

Trust is earned structurally, not asserted loudly. Verification badges are small and factual. Compatibility scores show their reasoning. Safety is designed into affordances, not marketed via anxiety-inducing copy.

🇮🇳
India-native

Not "India-adapted." INR-first, Devanagari-ready, mid-range Android performant. Spiti Valley and Kedarnath are primary content, not "exotic" content. The default audience is 24-year-old Puneet on a Redmi Note.

⚡
Decisively simple

Every screen has one clear primary action. Mixed digital literacy demands that the right move is obvious before the user has to think. Complexity is a product decision, not a design one — the UI never adds it.

The core tension
Adventure energy vs. safety trust — resolved by design.

Warm teal anchors trust (consistent, calm, reliable). Coral activates energy (CTAs, discovery moments). Indigo signals intelligence (AI match, compatibility). The system never uses red for energy — red is reserved for errors only.

07 — Motion

Motion principles

Motion reinforces personality. Three principles that resolve the adventure/trust tension through time and movement. All timings are fast by consumer app standards — this audience is on 4G, sometimes 2G, and mid-range hardware. Heavy animation = broken UX.

01
Purposeful, never decorative

Every transition communicates something: a new page arriving (fade-up 250ms), a match accepted (scale pulse 150ms), a message sending (slide-left 120ms). Nothing moves just to show off.

Enter (pages): opacity 0→1 + translateY 10px→0, 250ms ease-out
Micro (buttons): filter brightness, 120ms ease
Sheet expand: translateY bottom→0, 320ms ease-out
02
Warmth through gentle easing

Avoid linear and harsh ease-in. Prefer ease-out (things decelerate as they arrive — feels calm) and gentle springs for cards lifting on hover. The feel should be "card rises to greet you," not "element slides in."

Page transitions: ease-out only
Card hover: translateY -2px, 120ms ease
Match score reveal: scale 0.8→1, 200ms ease-out
Never: bounce, spin, elastic spring
03
Instant feedback for trust

Connection requests, chat sends, and payment clicks must respond in <100ms visually (optimistic UI) even if the API takes longer. Trust is built by immediacy. Spinners only for data loads — never for interactions.

Button press: immediate brightness change
Request sent: optimistic badge, 0ms delay
Chat message: bubble appears instantly
Skeleton: shimmer 1.4s linear, shown >200ms loads
08 — Surface Adaptations

Four surfaces, one token set

Same primitives everywhere. Semantic roles shift per surface — the admin console uses the same teal token but almost never shows it, while the marketing site leads with it. Layout density, type scale, and information architecture are what truly separate the surfaces.

Marketing Website
Acquisition · Drive app download + partner discovery
Display-size type (52–60px heroes). Bricolage Grotesque at max weight.
Ambient blobs (peach, sky, mint, lavender) — only surface that uses decorative gradients.
One dark full-width CTA section ("Get the app") + coral energy pill badges.
Glassmorphic topbar (72% blur). Sticky. Converts to solid on scroll.
Primary CTA: "Find your trip" (teal). Secondary CTA: "List your trips" (coral, partner-facing).
Blob backgrounds ✓ Decorative gradients ✓ Dense data tables ✗
Consumer App
Community-first · Social warmth · Matchmaking energy
People come first: faces and names above trip specs in match cards. Avatar + name is the primary visual unit.
Bottom nav (5 tabs). No sidebar. Every screen has a single floating primary action.
Match score (teal/amber/gray) is always visible on profile cards. AI reason pills shown prominently.
DIY path uses coral exclusively — creates a distinct visual mode that signals "you're building something."
Topbar: glassmorphic. Background: animated ambient blobs (low opacity, behind content).
Social components ✓ Coral DIY mode ✓ Admin density ✗
Partner CRM
Professional tool · Progress-oriented · Confidence-building
Opaque #F7F8FA background — no blobs. Clean SaaS layout. Operators need to focus on their data, not the aesthetic.
KPI tiles across the top (5 cols): Total, Published, Draft, Upcoming, Total Bookings — always visible.
Trip editor is a multi-section scroll (Details → Itinerary → Pricing → Media → Publish) with sticky action bar at bottom.
Publish validation errors surface as a pre-flight checklist in red — never silent failures. Save indicator shows "Saving…" / "Saved" in faint text.
Opaque BG ✓ Table views ✓ Blobs ✗
Admin Console
Dense, efficient, audit-aware · Never confused with consumer app
Dark sidebar (#14202A) immediately signals "this is not the consumer app." Shared token, different semantic role.
Information density is acceptable here. 13px body, 11px caption, compact table rows (40px height).
Audit logs: monospace font, immutable row styling (gray background + lock icon). No edit affordances visible.
Destructive actions (revoke session, deactivate partner) require 2-step confirmation. Red is used more than any other surface — appropriate here, where errors have consequences.
RBAC visual: role pills (9 roles) color-coded by permission tier. Super Admin = ink dark. Read-only = gray.
Dark sidebar ✓ Dense tables ✓ Blobs ✗ Warm tone ✗
09 — Design Principles

The four principles

These four principles are the QA filter. Every screen in the product can be evaluated against them. A screen that fails one should be redesigned before shipping.

01
People over places

Every screen that surfaces travellers should show a human face and a real name before it shows a destination. The community is the product.

02
One clear next step

No screen ends in a dead end. No view has two primary actions competing for attention. The hierarchy of actions is always visible and unambiguous.

03
Trust through transparency

AI scores show their reasons. Verification badges are factual, not marketing. Prices are complete (per person, inclusive of what). Never obscure anything that affects a traveller's safety or money.

04
Earned by 375px

If a design doesn't work on a Redmi Note at 375px width on a slow connection, it doesn't work. Mobile is not a constraint — it's the primary canvas. Every layout decision starts there.
