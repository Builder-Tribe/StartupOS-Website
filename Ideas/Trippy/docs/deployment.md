# Development & Deployment

> Truth source: root `trippy/package.json` (scripts), `trippy/render.yaml` (production).

## Local development

Requires **Node 22+** (uses built-in `node:sqlite`; the `NODE_OPTIONS=--experimental-sqlite` flag
is baked into the npm scripts).

```bash
cd trippy
npm install
npm run dev        # concurrently: server (:4000), web (:5173), website (:5174)
```

- Individually: `npm run dev:server` / `dev:web` / `dev:website`.
- URLs: consumer `http://localhost:5173`, partner `/partner`, admin `/admin`,
  API health `http://localhost:4000/api/health`, marketing site `:5174`.
- The DB auto-creates and seeds on first server boot. Demo logins: root [README](../README.md).
- `npm run reset-db` wipes the local database — **the dev DB can hold real accounts; never run
  this without explicit consent.**
- Machine-specific quirks (local Node path, npm registry mirror) belong in
  [`CONTRIBUTING.md`](../CONTRIBUTING.md), not here.

## Production (Render)

`trippy/render.yaml` defines a **single combined service**:

- Build: `yarn install && yarn workspace web build` → `web/dist`
  (production uses **yarn**; `yarn.lock` is the committed lockfile — keep it updated when
  dependencies change, even if you use npm locally).
- Start: `yarn workspace server start` — the Express app serves `/api/*` **and** statically serves
  `web/dist` with an SPA fallback, so one origin/port hosts everything.
- Health check: `/api/health`.
- Env: `NODE_VERSION=22`, `JWT_SECRET` (generated by Render — never commit one),
  `TRIPPY_DB_PATH=/var/data/trippy.db` on a 1 GB **persistent disk** (SQLite survives deploys).
- The marketing site (`website/`) is deployed as a static site on Render or Vercel.

## Environment variables

| Var | Default | Purpose |
|---|---|---|
| `PORT` | `4000` | API port |
| `JWT_SECRET` | loaded from `.env` locally; generated by Render in production | Signing secret for all three token realms — **required, no fallback** |
| `TRIPPY_DB_PATH` | `server/data/trippy.db` | SQLite location |
| `TRIPPY_TEST` | unset | Set by tests: skips `listen()`, app created via `createApp()` |

## Scaling path (when needed, not before)

SQLite-on-disk means **one instance** — no horizontal scaling. That's fine for the current stage.
The designed exit is Postgres/Supabase (see [architecture.md](architecture.md) seams and
[decision-log.md](decision-log.md)); until then, don't add infra (queues, caches, containers)
speculatively.
